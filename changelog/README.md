# 更新日志

每个版本单独保存为 `版本号.md`，例如 `0.4.4.md`。全部历史文件保留，发布脚本只读取与 Mod 版本号一致的那一份，不修改或删除历史记录。

新版本文件示例：

```markdown
# 0.4.5

- 写明本次面向玩家的变化。
```

文件名和第一行版本号必须一致。内容较多时，可以在文件内使用「新增」「调整」「修复」等二级标题，只保留本次有内容的分类。避免把提交记录直接当作玩家说明，不预先填写尚未确定的发布日期。

当前历史记录根据本地保留的版本映射和说明整理，不代表每个版本都曾在 GitHub 发布。

参考 [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) 的面向读者、按版本组织原则，以及 [Towncrier](https://towncrier.readthedocs.io/en/latest/) 的分文件维护思路。本项目采用简单的按版本分文件，不依赖这些工具，也不会将文件重新合并成总日志。
